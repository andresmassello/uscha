IThe Approachstations 01–04 · before a line is built
Start before the spec

The expensive failure is a confident build of the wrong shape. So station one isn't a document — it's a conversation that turns a vague idea plus references into a proposed shape the human accepts, bends, or rejects.

The order is the argument: idea → discovery → shape → spec → build → verify → evidence → human gate.

Discovery grills youin the kit

/discovery (idea → shape) and /adr-refine (known shape → sharp edges) produce clarity, never code.

Grill, don't agree. A discovery where the assistant agreed with everything failed — an agreeable interviewer just returns your blind spots as a plan. Friction is the product.

The conversation crystallizes into repo files

Truth is serialized to disk as decisions settle — the build reads files, not chat, because a new session, a /clear, or a compaction erases the transcript. Sub-agents and CI read files; a teammate next week has files.

CONTEXT · DOMAIN-MODELGlossary + the approved shape (entities, relations).
SPEC.mdBehavior, I/O, errors, acceptance, rollback.
docs/adr/*.mdOne per durable decision — executable, with an Implementation Plan.
ACCEPTANCE · RISKS · HANDOFFDoD (what readiness measures), residual risk, read-first rules.
The truth lives in versioned files. Chat is where thinking happens; the repository is where it's remembered.
SPEC ≠ ADR

Observable behavior → SPEC. A choice between alternatives → ADR. Write an ADR only if it's hard to reverse, surprising without context, and a real trade-off — all three, or it's noise.

Constitution above allin the kit

An ADR chooses; the CONSTITUTION forbids. Invariants no decision may override, CWE-mapped since 1.1.0. A violation logs a BLOCKER — caps readiness ≤65, blocks convergence.

IIThe Buildstations 05–07 · the inner loop & its evidence
Rigor scales to blast radius

Opening question: what can this break, and what does the break cost? The answer sizes the apparatus — profile A doesn't drag the full machine.

A · lowminor UI / config → build + test
B · normalfeature / bugfix → tests + static + review
C · criticalpayments / security → +integration +security +rollback
D · multi-systempublic API / events → contract tests + versioning
E · legacyrefactor / migration → characterization + no-regression
/dev-loop convergesin the kit

Takes ADRs + acceptance, builds, runs a severity-gated review cycle that stops. Three laws: converge don't chase zero · tests are a guardrail · generating tests ≠ running them.

plan → coverage gate → build → QA loop → integration → verify → PR, then stop. Oscillation (period-2 fingerprint) is detected; a clean cycle + clean static gate = done enough.

  • Ralph Wiggum loop: the "done" token fired too early — only an objective gate closes it.
Evidence, not narration

If the maker writes its own report card, it can log success having run nothing. So qa_ledger.py parses real artifacts — JaCoCo, Surefire, the linters — never the agent's claims.

Absent = no evidence, never "OK". A tool that didn't run is never invented as green.

Maker ≠ checker: a fresh-context checker graduates the work, not the maker. Anthropic's evaluator-optimizer, Dec 2024.

Facts block; guesses advise

A gate over a fact may stop the work; a gate that guesses over prose may only advise — because a heuristic that blocks throws false positives, the dev disables it, and a dead gate is worse than none.

golden-diff · pit-check · static gateread bytes / mutation XML / normalized linters → BLOCK
spec-check · abstractionsheuristic over prose → ADVISE

One uncorrelated checker caught 93.4% of what four caught (Osmani) — stack different opinions, not similar linters. Fact gates run in CI, not in the dev's face.

IIIThe Anchorthe one check the agent can't author
Golden testingnew

Everything else in the method is agent-authored. The golden is the exception — and that's the entire point. It captures what the old code actually does (bugs and quirks included) by running it, freezes it as a human-approved .approved, and diffs the migration against it byte-for-byte.

Why it's sacred: if the agent authored the golden, it would encode the same partial understanding that lost the logic — and pass against its own mistake. It's a check on the agent, not one it grants itself.
  • Never let the agent generate or edit .approved — a PreToolUse hook denies the write.
  • Never capture by reasoning — capture by executing against real production corpus.
  • Pin locale es-AR, freeze clocks, normalize GUIDs and map-order before serializing.
  • Add *.approved.* binary to .gitattributes — otherwise line endings lie.
IVThe Frontierstation 08 & beyond · autonomy, with the human at the gate
Autonomy earns its cost — or costs moreproposal

The outer loop is a heartbeat that fires the inner one on a cadence. Build it only when all four hold, or it costs more than a prompt by hand:

  • Repeats weekly+ · automated verification exists · budget absorbs the waste · agent has senior tools (logs, repro env).
> /loop 0 3 * * *          # nightly
  /goal readiness ≥ 80 AND 0 CRITICAL   # separate model
  stop    = goal met (fresh checker) OR budget out
  human   = merge/deploy ALWAYS with approval
The security tax

An unattended loop is an unattended attack surface. It enters as an operational layer of the constitution: SAST + secret-scan + dep-audit before any PR; vet every skill's origin (520 of 17,022 audited leaked creds); non-verbose logs; re-audit perms every 30d, start read-only; rotate the session before it bloats.

Your terrain is gated by design

Fiscal/e-invoicing, payments, critical retail all sit on the "do not autonomize" side the playbook itself marks. Gated-by-design isn't a gap — it's the decision. Metric once automated: cost per accepted change; below 50% accept, the loop is losing.

Where the method steps aside

Spike — no spec, just a note of what you learned. Prototype — marked, isolated, death-dated. P0 hotfix — fix first, but minimum evidence + retroactive SPEC/ADR within 24h. A designed escape valve keeps the method honest; an improvised one destroys it.
