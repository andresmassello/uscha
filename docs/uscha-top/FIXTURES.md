# FIXTURES — the `uscha top` oracle plan (governed by ADR-034)

The oracle for `uscha top` is golden frames: `render(state, size)` (pure, ADR-034) over a fixed
`top --json` object, snapshotted and asserted byte-identical in the smoke suite. This file names the
synthetic ledger fixtures, what each pins, the golden-frame matrix, the negative honesty cases, and
the before/after `curate` write-equivalence fixture. All names are generic (`backend-api`,
`mobile-app`) per repo rule 4.

Home (**shipped in M1**): `uscha-kit/tests/fixtures/uscha-top/` — one directory per ledger
fixture, `state/` for the frozen `top --json` objects the renderer is snapshotted against, and
`golden/` for the frame snapshots.

## 1. Synthetic ledger fixtures

Each fixture is a minimal ledger (plus a `CANDIDATE-DELTA.json` where quarantine is involved) that
`qa_ledger.py top --json` reads to produce a deterministic JSON `state`. Each fixture repo tree
carries **only** its ingested `reports/junit.xml` and no source file: with no source, the engine's
mtime freshness correlation is skipped entirely, so a checkout that rewrites mtimes cannot flip a
criterion between MEASURED and UNMEASURED.

**Shipped in M1 (3):**

- **F1 — healthy** (`fixture-healthy/`, 6 obligations): all `MEASURED_PASS`, no quarantine, no
  UNMEASURED. **Pins:** a legitimately full board — `DONE 6/6 (100%)` with **no** suffix (allowed by
  INV-TOP-01 precisely because nothing is outside PASS), `debtors {0,0,0}`, `eta_min:null` → `ETA —`,
  green-only board colors. This is the one frame where 100% is honest; it guards against a renderer
  that refuses to ever show 100%.

- **F2 — stale quarantine** (`fixture-stale-quarantine/`, 8 obligations): 2 `MEASURED_PASS`, 1
  `MEASURED_FAIL`, 2 `QUARANTINE` (uncurated observations heuristically matched to ACs), 3
  `UNMEASURED`, plus a third observation with `ac:null`. **Pins:** all four debtor buckets at once,
  the per-state colors, `AGE —` on every row (v0.1), `ac:null` rendered honestly (no fabricated
  link), and the only real median in the set (`medians.loop_min: 40`, from three iteration
  timestamps).
  **Extended in M2:** seven `steps` — snapshot, three qa-steps, a not-run gate, a gated static gate
  and an escalation — chosen so the feed shows **all five levels at once** (`P F H U I`); the
  matching iteration/escalation records carry the `n` the engine correlates by. The three original
  iteration timestamps are untouched, so `loop_min` is still 40 and no other assertion moves. This
  is also the fixture whose 80×24 frame proves the degradation rule with real content: the feed
  shows `5/7` while the board keeps all eight rows.

- **N1 — honesty negative** (`fixture-honesty-negative/`, 24 obligations): 23 `MEASURED_PASS` + 1
  `UNMEASURED`. See §3 — this is the discriminator, not a happy path.

**Planned — M2/M3, not shipped:**

- **F3 — re-pinned scope** (`fixture-repinned-scope/`) *(planned)*: a `readiness_history` with a
  score step across a spec re-pin, and a changed obligation denominator. Would pin a denominator
  differing from F1/F2/N1 so the fixed-per-commit `|O|` is exercised. M1 covers the score burn-up
  and the honesty-beside-DONE rule through F1/F2/N1, which already carry three different
  denominators (6, 8, 24).
- **F4 — real demo module** (`fixture-demo-module/`) *(NOT NEEDED — superseded by M3)*: the demo
  module's real ledger, end-to-end. It was drafted as the fixture that would exercise the event feed
  from real `ledger["steps"]`. M2 shipped the feed without it: F2's synthetic steps cover the five
  levels deliberately, and T137's in-memory ledger covers the kinds, the unknown kind, the offset
  timestamp and the injected control sequence — none of which a real ledger can be made to carry on
  demand. M3 did not need it either: the VERDICTS queue wants a real `CANDIDATE-DELTA` that can be
  WRITTEN to, and a temp copy of F2 is exactly that — with the committed fixture left read-only.
  Nothing in v0.1 is waiting on this fixture; it is recorded here as considered and declined.

**Frozen states** (`state/`): `state-healthy.json`, `state-stale-quarantine.json`,
`state-honesty-negative.json` are verbatim `top --json` output with the two volatile members
(`generated_at`, the git sha inside `spec_pin`) normalized to fixed values. `state-traced-tagged.json`
is the one **deliberately forced** state: it carries a `TRACED` rung, a `TAGGED` rung and a null
`spec_pin` — three things the v0.1 engine can never emit — so the renderer's promise that those
rungs read gray and never PASS is measurable (§3, AC-T-08, AC-T-06).

`state-empty.json` (added post-M1, curated with the F1-F5 fix pass): a genuinely EMPTY project —
zero tagged obligations, no observations, no burn-up history, `spec_pin: null`. It exercises the
board's own edge, not another obligation's state: DONE `0/0 (0%)` with no `unmeasured` suffix (0
divided by 0 is not "some unmeasured", INV-TOP-01 does not fire), the "no tagged criterion in the
acceptance file (nothing to measure yet)" table line, and no fabricated `100%` anywhere in the
frame. Golden frames at both sizes are generated by `render()` itself, the same oracle as every
other fixture here.

`state-wide.json` (added 1.90.0, undocumented until the 1.91.0 blind review): the fixture the
display-width work needed and did not have — a CJK project name, a full-width gate cell and a CJK
feed line, so every width computation is exercised in **columns** and not in codepoints. It travels
with the others through the golden oracle (AC-T-19) and the frame-geometry criterion (AC-T-21).

## 2. Golden-frame matrix

`state × size × mode`. Sizes: 100×32 (reference), 80×24 (degradation floor). Modes: BOARD only in
M1; VERDICTS frames arrive with VERDICTS mode (M3).

| Frozen state | 100×32 BOARD | 80×24 BOARD | 100×32 VERDICTS | 80×24 VERDICTS | DIFF (both sizes) |
|---|---|---|---|---|---|
| F1 healthy | ✓ shipped | ✓ shipped | — (empty queue) | — | — |
| F2 stale quarantine | ✓ shipped | ✓ shipped | ✓ shipped (M3) | ✓ shipped (M3) | — (no drift record) |
| N1 honesty negative | ✓ shipped | ✓ shipped | — | — | — |
| forced TRACED/TAGGED + null pin | ✓ shipped | ✓ shipped | — | — | — |
| empty project (0 obligations) | ✓ shipped | ✓ shipped | — | — | — |
| wide (CJK / full-width text) | ✓ shipped (1.90.0) | ✓ shipped (1.90.0) | — | — | — |
| **drift (F2 + a real `spec-drift` run)** | — | — | — | — | ✓ shipped (1.91.0) |
| F3 re-pinned scope | planned | planned | — | — | — |
| F4 demo module | not needed | not needed | not needed | not needed | — |

Ten frames ship in M1 (eight from the original four states, two from `state-empty.json`), two
more in 1.90.0 (`wide-100x32` / `-80x24`, the display-width fixture — the row above went
undocumented when it shipped and is recorded here now), two more in M3
(`stale-quarantine-verdicts-100x32` / `-80x24`) and two in phase 2
(`drift-100x32` / `-80x24`) — **sixteen** in total: twelve BOARD, two VERDICTS, two DIFF. The
fourteen BOARD/VERDICTS frames are asserted byte-identical by T138 (board) and T141 (verdicts),
the two DIFF frames by T145.
Only the drift state has a DIFF frame, and that is the whole population that can have one: the
other frozen states carry no `spec_drift` record, and their pane is the *empty* case — pinned by
assertion in T145 rather than by a seventeenth and eighteenth file that would differ from the drift
frames in exactly one line. The 80×24 frames assert the degradation rule (AC-T-21): the layout holds,
the frame is exactly 24 lines, no line exceeds 80 columns, and the feed is what shortens — the
header and board are never the first casualty. The two VERDICTS frames pin the other degradation:
at 100 columns candidate and evidence sit side by side; at 80 they stack, because a 37-character
column is a word per line and not a pane.

Only F2 has a VERDICTS frame, and that is the whole population that can have one: a queue frame
needs uncurated observations, and F2 is the only fixture whose ledger carries a delta. F1's queue
is empty by construction, N1 and the forced states carry none — a frame of an empty queue would
pin the "nothing uncurated" line and nothing else, which the dispatch assertions already cover.

## 3. Negative honesty cases

These exist to fail a cheating implementation, not to describe the happy path.

- **N1 — 23/24 + 1 UNMEASURED** (`fixture-honesty-negative/`): 23 `MEASURED_PASS`, 1 `UNMEASURED`.
  Golden frame MUST render `96%` with the `· 1 unmeasured` suffix and MUST NOT render `100%`
  (AC-T-23, INV-TOP-01/02). A renderer that rounds or drops the unmeasured obligation fails here.
- **Verdict does not move DONE** *(shipped M3, measured in T141 over a TEMP COPY of F2)*: a real
  verdict is recorded through the TUI's write path and `top --json` is re-read; `terminado.done` and
  `terminado.pct` are unchanged and only the debtor cardinalities move — `you` down by one, the four
  buckets still partitioning the board (AC-T-16, INV-TOP-03). Asserts there is no auto-rerun. It
  works on a copy rather than on a frozen state because what it measures is the WRITE: a paired
  render of two hand-made states would prove only that two files differ where a human made them
  differ.
- **Null medians → `ETA —`** *(shipped: F1, F2, N1)*: every state renders `ETA —` because
  `medians.verdict_min` is null; no fixture is allowed to render a numeric ETA in v0.1 (AC-T-03).
- **TRACED/TAGGED → gray, never PASS** *(shipped: `state/state-traced-tagged.json`, both sizes)*:
  the two rungs are forced into the state by hand precisely because the engine cannot emit them;
  each renders in the UNMEASURED-class gray, never green (AC-T-08).
- **spec_pin null → `—`** *(shipped: the same forced state carries `spec_pin: null`)*: the header
  renders `spec_pin —`, never a fabricated SHA (AC-T-06, INV-TOP-05).
- **Zero obligations → `0/0 (0%)`, never `100%`** *(shipped: `state/state-empty.json`, both
  sizes)*: an empty denominator is not a full board; the frame must show the "nothing to measure
  yet" line and must never let `0/0` round up into a fabricated `100%`.
- **Feed crowded out of the frame → the pane says so** *(shipped M2, measured in T138 over a
  SYNTHETIC state, not a file)*: no shipped fixture has both a long board and a non-empty feed —
  N1 has the obligations and F2 has the events — so the case is built in the test by giving N1's
  obligations F2's `events_tail`. At 80×24 the board eats every feed line and the label must read
  `feed · 0/7 · no room at this size`, never the empty-ledger label: "nothing recorded" and "no
  room to show it" are different statements. It lives in the test rather than in `state/` because
  a frozen file nobody generates from a real `top --json` is a fixture whose provenance is a
  hand edit; as a synthetic in the assertion, what it is made of is visible at the point of use.
- **No spec-drift run → the pane says so, never a clean board** *(shipped 1.91.0, measured in
  T145 over a synthetic built by dropping `spec_diff` from the drift state)*: the frame must
  carry `no spec-drift run recorded` and name the command that would produce one, and must NOT
  carry a `N of M doc(s) stale` line. "Nobody measured" and "nothing is stale" are different
  statements and only one of them is ever free (INV-TOP-05). The engine half of the same rule is
  asserted beside it: a ledger with no `spec_drift` record emits `spec_diff: null`.
- **A rerun that exits red is still ingested** *(shipped 1.91.0, measured in T145)*: the status
  line names the exit code and the ingest happens anyway. A renderer that showed the previous,
  greener measurement after a red run would be narrating; the discriminator is the assertion that
  the snapshot boundary is reached on a non-zero exit too.
- **A hostile frozen state cannot widen a line or smuggle an escape** *(shipped M2, measured in
  T138 over a synthetic)*: `render()` also renders state FILES, so every string the state supplies
  (`project`, `spec_pin.sha`, an obligation `id`/`gate`, an event `ts`/`text`) is a way to falsify
  "no line wider than `cols`" and to plant an escape in a frame the golden oracle compares as
  text — the final width pass deliberately leaves coloured lines alone. The case feeds a 300-char
  ESC-prefixed sha, a 200-char project and a 400-char event text, and asserts the frame is still
  exactly `rows` lines, no line over `cols`, and zero ESC/NUL on the plain path.

## 4. Before/after `curate` write-equivalence fixture *(shipped M3, T141)*

Proves the TUI reimplements no append logic (ADR-033).

- **Setup:** TWO temp copies of `fixture-stale-quarantine` (ledger + `discovery/CANDIDATE-DELTA.json`
  with three known uncurated OBS). The committed fixture is never written to.
- **Path A (manual):** `qa_ledger.py curate --ledger QA-LEDGER.json --repo backend-api --obs
  OBS-XXXX --verdict preserve --human operator --note "recorded via uscha top"` on copy A.
- **Path B (TUI):** `apply_verdict()` on copy B with the same observation and the `p` verdict, which
  shells out to that same invocation.
- **Assertion:** the two appended records are identical **member for member**
  (`{obs_id, verdict, human, note, repo}`) and carry exactly those members plus `at`. `at` is the one
  member that cannot be equal — it is a wall clock read inside a subprocess, and the suite injects no
  clock across a process boundary — so it is asserted for SHAPE (present, a string, the same length),
  not for value. Saying that plainly is cheaper than claiming a byte-equality the fixture does not
  produce. Beside it, AC-T-15 asserts the TUI path produced exactly ONE `curate` spawn per keypress —
  never a batch — and that the module has no other write path at all (no file opened for writing, no
  JSON dumped, exactly one `curate` argv in the source).

## 5. Input / dispatch fixtures *(shipped M3, T141)*

The terminal driver (`termios`/`msvcrt`) is not tested; the dispatch is (ADR-034).

- Keys are fed to `dispatch_mode(key, mode, sel, count)` directly — the pure mode machine over the
  board keymap (`dispatch`, unchanged and still measured on its own by AC-T-22). `v` enters,
  `t`/`Esc` returns, `j`/`k`/`1-9` move, `p`/`f`/`u` produce a verdict string and nothing else.
- **Assert:** the transitions (BOARD→VERDICTS→BOARD, the selection index), that a non-verdict key
  produces no verdict at all, that an EMPTY queue produces no verdict from `p` either, and the exact
  `curate` argv the keypress emits — with the subprocess boundary replaced, so no ledger is written
  (that is §4's job).
- **The held key** (the hazard a blind review found): after a verdict the input buffer is drained and
  `p`/`f`/`u` are refused for 250 ms. Measured purely — the cooldown enters `dispatch_mode` as a
  caller-supplied boolean, so no clock enters the dispatch: a first `p` yields `preserve`, the
  repeats yield nothing and move no cursor, and exactly one `curate` call is spawned for the three
  keypresses. `drain_keys()` itself is measured only for what a suite without a terminal can honestly
  observe: it answers with a bounded count, does not raise and does not block.
- **What is NOT measured, and is said so:** the interactive `_loop` itself. It needs a terminal the
  suite does not have; every decision it makes is factored into pure functions (`dispatch_mode`,
  `verdict_queue`, `apply_verdict`, `after_verdict`, `render`) that ARE measured, and the loop is the
  thin wiring between them. A test that claimed a driven TTY session would be the over-claim the
  golden frames exist to prevent — the same line M2 drew for the poll.

## 6. Determinism notes

- Every fixture's `top --json` must be interpreter-stable (the repo's cross-platform discipline;
  `os.path.realpath` both sides of any path comparison — CLAUDE.md Windows 8.3 gotcha).
- The smoke assertions that check these frames must parse under bash 3.2: no `${`, no backticks, no
  quote inside a bracket expression in the heredocs (CLAUDE.md known gotcha). Golden frames are stored
  as files and compared, keeping the heredoc logic minimal.
