# ADR index

Every architecture decision in this repo, grouped by who needs it. The folder is flat and the numbering is chronological — prose across the repo cites ADRs by number, so files are never moved or renumbered. This index is the map over that flat folder.

**New here? Five ADRs are enough to work with the method:**

1. **[ADR-001](ADR-001-risk-profile-modulates-flow.md)** — how a risk profile modulates the flow. Start here: it is the one knob that changes what every later gate does.
2. **[ADR-003](ADR-003-fast-path-measured-entry.md)** — how a trivial change earns the fast path. The clearest example of the house rule: a measured signal opens the gate, never an opinion.
3. **[ADR-009](ADR-009-candidate-specs-in-quarantine.md)** — what an agent may author about a system it did not write, and the human verdict that stands between a candidate and the contract.
4. **[ADR-038](ADR-038-terminado-sealed-evidence.md)** + **[ADR-039](ADR-039-freshness-by-content-and-commit.md)** — why DONE is not DONE while the seal is broken, and how the engine decides a report is still current. Together they are the freshness rule the whole ledger rests on.
5. **[ADR-040](ADR-040-stack-lifecycle-round.md)** — the stack as a decision with an expiry date. The newest of the five and the one most likely to change how you run discovery tomorrow.

Statuses below are copied verbatim from each ADR, amendment chains included. The index is regenerated per release: it describes the ADRs present at this release, not a plan for the next one.

## Method (read these)

The decisions a consumer of the kit needs. These govern the engine and the loop: what gates, what only advises, what an agent may author, and what only a human may approve.

| ADR | What it decides | Status |
|---|---|---|
| [**ADR-001**](ADR-001-risk-profile-modulates-flow.md) — The risk profile modulates the flow (kit-shipped, overridable presets) | `risk_profile` is a **named preset**, not a new gating mechanism: at config load the selected profile expands into knobs the config already understands. | Accepted — **amended 2.0.0: `init` generates a minimal config so the profile is not pre-empted by copied defaults** |
| [**ADR-002**](ADR-002-golden-required-cap.md) — `golden_required` — a declarable cap for "an approved golden must exist" | Adds `golden_required` as a declarable readiness knob; when it is active and no approved `golden-diff` gate is recorded, that repo's readiness is capped at 49 (NOT READY). | Accepted |
| [**ADR-003**](ADR-003-fast-path-measured-entry.md) — Fast-path entry is granted by measured signals, never by opinion | `/uscha-devloop` gains a fast-path mode, entered only when `fastpath-eval` returns `ALLOW` from measured signals — files changed and LOC delta read from `git diff --numstat`, never self-reported. | Accepted |
| [**ADR-004**](ADR-004-defer-golden-touched-veto.md) — The golden-touched veto is deferred until a golden↔source mapping exists | Phase 1 ships **without** `forbid_when_golden_touched`; the fine-grained case waits until characterize records a coverage mapping at capture time. | Accepted |
| [**ADR-005**](ADR-005-spec-drift-advisory.md) — Spec drift is detected mechanically and reported as advisory — never gated | New subcommand `spec-drift`: the mapping is an explicit `governs:` glob list in frontmatter, and a file with no frontmatter reports `UNMAPPED` — which is not the same as "no drift". | Accepted |
| [**ADR-006**](ADR-006-golden-coverage-measured-mapping.md) — The golden↔source mapping is DERIVED BY MEASUREMENT, and the veto it unblocks is opt-in | `/uscha-characterize` runs the harness under `coverage.py` while producing the `.received` and records the measured file list in `golden.coverage.json` at the repo root. | Accepted |
| [**ADR-007**](ADR-007-evidence-origin-and-deferred-cleanroom.md) — Evidence records the commit and tree state it was measured at; the worktree clean-room is deferred | `_snapshot`, the single ingestion choke point, stamps `origin: {commit, dirty}` measured from `git rev-parse HEAD` and `git status --porcelain`; untracked files count as dirty. | Accepted |
| [**ADR-008**](ADR-008-cleanroom-verifies-the-commit.md) — The clean-room verifies the COMMIT, and the engine never decides what to run | `cleanroom --repo <r> --ref <sha> --run "<command>"` creates a detached worktree of the exact commit, runs what it was given, and records the result with full provenance. | Accepted |
| [**ADR-009**](ADR-009-candidate-specs-in-quarantine.md) — The agent may author CANDIDATE specs of a legacy system — in quarantine, behind a measured promotion gate | Candidates live in `discovery/` and **are not specs**: each carries evidence type, verifiable refs and confidence, and nothing reaches the contract without a human verdict. | Accepted |
| [**ADR-010**](ADR-010-behavior-ledger-strict-form.md) — The behavior ledger is a human-readable markdown table with machine-enforced rules | `BEHAVIOR-LEDGER.md` at the project root, in a strict shape the engine parses: a malformed ledger is `exit 2`, never a silent degrade to "no verdicts". | Accepted |
| [**ADR-011**](ADR-011-no-shared-extraction-engine.md) — There is no shared behavior-extraction engine — spec-drift and reverse discovery stay separate instruments | Extraction stays **skill** work (LLM, judgment) per ADR-009 and spec-drift stays exactly as built (engine, dates, advisory); the shared identity is one of idea, not implementation. | Accepted |
| [**ADR-012**](ADR-012-system-facts.md) — Published claims are compiled artifacts of derived facts (SYSTEM-FACTS) | `facts` derives `SYSTEM-FACTS.json` **from the artifacts themselves, never from prose**, and carries no timestamp — so regeneration over an unchanged repo is byte-identical. | Accepted |
| [**ADR-013**](ADR-013-candidate-delta-typed-observations.md) — Discovery emits a typed CANDIDATE-DELTA; verdicts become ledger objects (supersedes ADR-010's storage, keeps its invariant) | The machine-canonical form of discovery output is `discovery/CANDIDATE-DELTA.json`: typed observations with statement, evidence class and provenance, mechanically derived, never hand-edited. | Accepted |
| [**ADR-014**](ADR-014-fidelity-vector-advisory-never-gates.md) — Fidelity is a vector of independent dimensions, and an advisory-class dimension can NEVER be registered as blocking | `fidelity` computes a vector of independent dimensions (traceability, behavior, ...) from artifacts the engine already holds after discovery and curation. | Accepted |
| [**ADR-036**](ADR-036-family-prefixed-criteria.md) — The instrument reads family-prefixed acceptance criteria — `AC-<FAMILY>-<n>` joins the bare `AC-<n>` in the measured pipeline, so a criterion the suite already proves stops reading as untagged | The canonical id grammar has two forms: bare `AC-<n>` and family `AC-<FAMILY>-<n>`, both normalised, so a criterion the suite already proves stops reading as untagged. | Accepted |
| [**ADR-038**](ADR-038-terminado-sealed-evidence.md) — TERMINADO is sealed to the exact code state — evidence files are content-hashed at ingest, and DONE is not DONE while the seal is broken (INV-T1, ported into the engine) | `snapshot` records a `sha256` per ingested report, and `top --json` gains `terminado.sealed = {ok, reasons[]}` recomputed at read time from what the ledger already carries. | Accepted (1.92.0; option B chosen by the maintainer 2026-08-19) — **amended 1.93.0: tolerant seal** |
| [**ADR-039**](ADR-039-freshness-by-content-and-commit.md) — Evidence freshness is decided by CONTENT and COMMIT, not by the clock alone — a report is current when no source changed since the run that produced it, whatever the files' mtimes say; and the seal tolerates commits that touch no source | Two freshness rules, either sufficient and both measured: the clock rule (report mtime at or after the newest source mtime) or content plus commit (the recorded `sha256` still matches). | Accepted (1.93.0; approved as written by the maintainer 2026-08-19) |
| [**ADR-040**](ADR-040-stack-lifecycle-round.md) — The stack is a decision with an EXPIRY DATE — a mandatory "Stack and lifecycle" round before the stack ADR, a machine-readable `lifecycle:` block, and a measured advisory that compares end-of-support against the declared go-live | A mandatory "Stack and lifecycle" round before the stack ADR, with every end-of-support date fetched from the official source as the question is asked, never answered from memory. | Accepted (1.94.0; proposed by the maintainer from a field run, approved 2026-08-21) |
| [**ADR-041**](ADR-041-dogfooding-freshness-by-ancestry.md) — The dogfooding criterion is decided by git ANCESTRY, not by a wall clock — and the release ritual is a script that refuses (I1..I8), not prose a human re-reads | `AC-DF-01` compares two COMMITS instead of a timestamp against a committer date, which removes the pre-suite `readiness --record` and the amend trap with it; `tools/release.py` performs the six steps and refuses naming the invariant. | Accepted (1.96.0) — **amended 1.97.0: I3 runs `facts --write` before the check** |
| [**ADR-043**](ADR-043-simplicity-advisory-by-default.md) — The simplicity score ADVISES by default — only a declared budget can make it gate, and `max_nesting` is named as the indentation proxy it is | `simplicity-check` exits 0 and reports unless the project declares a numeric budget AND `defaults.simplicity.gate: true` (a gate with no budget is refused, exit 2); the score is untouched, `max_nesting` is labelled the indentation proxy it is, and `log-gate --verdict advisory` records a measured, non-gating run that never reads as `ok`. | Proposed |
| [**ADR-044**](ADR-044-ask-for-decisions-not-information.md) — The agent asks for DECISIONS, never for INFORMATION — and a decision the human never made carries `origin: agent` until they confirm it, item by item | Information the tree holds (the current version of a tracked `.md`) is READ, never asked; every acceptance criterion, ADR decision item or `HANDOFF.md` rule the AGENT introduced carries `(origin: agent)` until a human confirms THAT item with `confirmed: YYYY-MM-DD`, and `spec-check` / `readiness` report the unconfirmed ones as ADVISORY — no exit code, no cap, no gate. | Proposed |
| [**ADR-045**](ADR-045-skill-blocks-carry-the-kit-version.md) — The generated orientation block carries the kit version, and the release script re-renders it — so an installed skill can be DATED | The generated `SKILL.md` region opens with `<!-- uscha kit: X.Y.Z -->` rendered from `uscha-kit/VERSION`; `tools/release.py` re-renders all 18 regions in step 2 (I3) and `gen-skill-blocks.py --check` is red when they lag; `doctor` reads the marker out of every install root and reports `current` / `outdated` (with both versions) / `not installed` — advisory, exit code unchanged. | Proposed |
| [**ADR-046**](ADR-046-corpus-run-field-truth.md) — Field truth for greenfield — a REAL-INPUT corpus is an evidence class, measured as a gate the project declares | New subcommand `corpus-run` scores a JSONL corpus of real inputs against a command and persists `gate:corpus`; the threshold is the project's (`--threshold`, else the repo's, else defaults) and with none declared the run is ADVISORY; a green run tagged `--ac` closes a criterion MEASURED, and `readiness` prints a conditional `field` line — no weight, no new cap, the `field` dimension deferred to its own ADR. | Proposed |
| [**ADR-047**](ADR-047-smoke-ingest-measured-evidence.md) — The smoke run is MEASURED evidence — executed, never narrated | Phase 7 stops producing a prose checklist: the project's own tool writes `reports/smoke.json` (`checks` with a `name` and a boolean `ok`) and `smoke-ingest` persists `gate:smoke` — a failed check caps readiness <=65 and blocks convergence, an empty or malformed report is exit 2 naming it, `smoke` is a FACT kind that refuses `--verdict advisory`, and a check named `AC-nn ...` closes that criterion MEASURED while a failed one VETOES it. | Proposed |
| [**ADR-048**](ADR-048-operability-measured.md) — Operability is a MEASURED dimension — CI, release, RUNBOOK and seed are facts in the tree, not phase-8 prose | New subcommand `operability --repo R` reads four FACTS out of the tree (a workflow running the repo's configured test command, a workflow publishing a release asset, a `RUNBOOK.md` naming start/config/rollback/smoke, a declared seed command whose script exists) and persists `gate:operability`; the posture is the profile's — advisory on A/B, a BLOCKER on C/D/E through the new profile-owned knob `defaults.operability.gate`. | Proposed |
| [**ADR-049**](ADR-049-codex-end-to-end-pilot.md) — A full end-to-end `/uscha-devloop` cycle ran on Codex, converged clean, and found five gaps in the surfaces Claude Code had never had to prove | `check-coverage` exits 2 (UNMEASURED) rather than a below-threshold verdict when no report exists; `uscha init` writes a scoped, per-repo-type `.gitignore` that never lists `reports/`; the orientation block states the no-statusline visible-reply rule for Codex/pi/plain terminals; the devloop SKILL instructs ticking measured-but-unchecked boxes before closing; `pr-ready` is documented, everywhere, as a phase value read through `phase --require pr-ready`, never a subcommand. | Accepted (2.4.0) |

## Research program (the Diamond)

The regeneration experiments — IR, the compiler contract, the bench, the controlled-language arm. Read these to understand the thesis and how it is measured; none of them is needed to USE the kit.

| [**ADR-016**](ADR-016-compiler-contract-v0.1.md) — The LLM is a compiler with a validated output contract; the engine validates and ingests compilations but never compiles, and only mechanical violations gate (Compiler Contract v0.1) | The compiler produces `compilations/<id>/COMPILATION.json` conforming to `compile/0.1`; the engine validates and ingests compilations but never compiles. | Accepted |

## `uscha top` internals

The terminal projection of the ledger: its data contract, its single write path, its render oracle. Read these only when changing the TUI.

| ADR | What it decides | Status |
|---|---|---|
| [**ADR-031**](ADR-031-uscha-top-tui.md) — `uscha top` is a raw-ANSI terminal projection of the ledger — no curses, no server, wired the way `mirador` is, so the programmer meets the method where they already live | A new terminal application `uscha top`, launched by a `top` subparser that resolves and execs `uscha_top.py` exactly as the mirador renderer is resolved, in both skill-tree layouts. | Accepted (M1 shipped in 1.86.0; the `mtime` poll shipped in 1.88.0 for M2; curated 2026-08-17) |
| [**ADR-032**](ADR-032-uscha-top-data-contract.md) — The engine computes the whole projection — one read-only subcommand `top --json` emits every state, cardinality, median and feed line already derived, and a field with no honest source is `null`, never invented | New read-only subcommand `top --json` (`cmd_top`) computes the full projection in the engine and prints one JSON object; it never writes, never runs tests, never calls a model. | Accepted (M1 shipped in 1.86.0; feed derivation amended and shipped in 1.88.0 for M2; `observations[]` amended and shipped in 1.89.0 for M3; `spec_diff` + `repos` amended and shipped in 1.91.0 for phase 2 / ADR-037; `terminado.sealed` amended and shipped in 1.92.0 / ADR-038; nullable fields per ADR-035; curated 2026-08-17) |
| [**ADR-033**](ADR-033-uscha-top-single-write-path.md) — The verdict is the only thing `uscha top` writes, and it writes it by shelling out to the existing `curate` — one keypress, one `curate` call, no batch, no auto-promotion, no auto-rerun | The only write the TUI performs is a verdict, and it performs it by `subprocess`-invoking `curate`; the TUI never opens the ledger for writing. | Accepted (M3 shipped in 1.89.0; curated 2026-08-17; title sentence restated for phase 2 in 1.91.0 per ADR-037) |
| [**ADR-034**](ADR-034-uscha-top-render-oracle.md) — `render(state, size)` is a pure function and its oracle is golden frames — the same discipline the kit uses on itself, so a cheating renderer that shows 100% is caught by a snapshot, not by trust | `render(state, size)` takes the parsed `top --json` object and a size and returns lines, with no file read, clock read, subprocess or environment lookup — so golden frames can be its oracle. | Accepted (M1 shipped in 1.86.0; curated 2026-08-17) |
| [**ADR-035**](ADR-035-uscha-top-deferred-persistence.md) — The facts `uscha top` renders as `—` in v0.1 are deferred on purpose — each needs new append-only engine persistence, and this ADR records the shape so the field is wired before it is re-claimed, never the other way round | Records the shape of the facts `uscha top` renders as `—` in v0.1 — starting with a per-observation first-seen timestamp — each needing new append-only engine persistence first. | Proposed |
| [**ADR-037**](ADR-037-uscha-top-rerun-trigger.md) — `o` rerun in `uscha top` — the TUI may TRIGGER the engine with a command the human supplied at launch; it never decides what to run and never writes the ledger itself (proposal for phase 2, M4) | Option B: `o` triggers a command the human supplied at launch and the engine ingests it; the snapshot runs whether or not the command exited 0, in the first configured repo. | Accepted (phase 2 shipped in 1.91.0; option B chosen by the maintainer 2026-08-18) |
