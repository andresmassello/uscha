# uscha-kit 1.90.0 — measured debt paid: the round trip reads behaviour (0.062 → 0.828), coverage measured at 85.9%, and three deferred issues closed (2026-08-18)

Batched on purpose (the release ritual is what costs hours; two releases' worth of work ship in one).
Everything below is measured by the suite; every number was regenerated by the engine.

## 1. The round trip attributes behaviour (ADR-030 amended)

The maintainer curated, archetype by archetype, which withheld-oracle case exercises which
acceptance criterion: 201 of 216 cases across the 12 archetypes now carry an `"ac"` tag (3 human
adjustments recorded in `ORACLE-TAGS-CURATED.json`; structural criteria — module shape, the
two-unit seam, a round-trip law — deliberately carry no case). Payload and expected outputs are
untouched; the bench verdicts are identical (9 PASS / 3 PARTIAL). `bench-roundtrip` now reads
tags from a case's name ∪ its `ac` list, normalised with ADR-036's own grammar on both sides of
the comparison, one oracle run per case (a case with three tags was being run three times).

Result: mean recoverability **0.062 → 0.828**, behaviour dimension **measured in 12/12** entries
(was 0/12), `ledger-lite` edges recovered 0.33 → 1.00. The honest reading, in ADR-030's words:
what changed is what the instrument can *attribute*, not what the artifacts *do*. The aggregate is
pinned as a range (0.827 under 3.8, 0.828 under 3.13 — the twelve means sum to 9.930; the
cross-interpreter tolerance is compared in integer thousandths because `abs(0.828-0.827) <= 0.001`
is false in IEEE 754, which the first attempt found out). `AC-RT-04` discriminates four ways
(strip the tags → UNMEASURED and 0.000; a tag on a passing case anchors, on a failing case it does
not; `ac_cs_1` matches node `AC-CS-01`). Two things found on the way: a hardcoded sentence inside
the generated report ("which today is every entry") is now derived from the aggregate; the round
trip left three `.pyc` files in a clean bench tree (`PYTHONDONTWRITEBYTECODE=1` for the judged
program). The scheduler oracle's byte-identical twins under `controlled-language/` received the
same tags (AC-SH-03).

## 2. Engine coverage: 57.6% → 85.9%, said honestly

The declared threshold was 60; the committed number was 58 for 25 releases (ISSUES-DEFERRED,
1.82.0). Measured now: `qa_ledger.py` 86.6%, `uscha_top.py` 73.2%, whole surface 85.9%
(`reports/coverage.xml`, regenerated). **Most of the jump is the instrument, not new tests**: two
measurement blind spots closed — auxiliary scripts and multiprocess children were not being
counted — plus T142–T144 (worth having; not what moved the number). No test was written to inflate
the figure; the threshold stays 60. The committed report predates the ADR-030 amendment by 21
statements (under half a point); it is re-measured at the next coverage release, not narrated.

Found while measuring: coverage.py's `.pth` starts a full `Coverage` in every python descendant
before any `sitecustomize` can opt out — including the ~14,000 compiled implementations the
withheld oracle judges, all outside every `--source` root, all empty by construction; on Windows
the process storm ended in `STATUS_DLL_INIT_FAILED` and made T136 red only under coverage. Fixed
at the boundary: the judged program's environment drops `COVERAGE_PROCESS_START`/`_CONFIG`
(`_judged_env`), pinned by a T127 check; data files per run 14,424 → 1,280.

## 3. Deferred issues closed

- **AC-GM-08 under `USCHA_COVERAGE=1`**: `golden-coverage` builds its child environment with
  `COVERAGE_FILE` set to its own isolated data file; green under both modes; `coverage xml` no
  longer needs `--ignore-errors` (kept as a cheap guard).
- **Display width**: `uscha_top` measures lines by display width (`east_asian_width`, combining
  marks 0, wide 2) and never splits a wide glyph; C1 controls and Unicode format characters are
  now filtered too (ADR-032/SPEC sentence updated: they were declared unfiltered in 1.88.0). A
  wide-glyph frozen state with goldens at both sizes pins it; every ASCII golden is byte-identical.
